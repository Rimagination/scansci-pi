# ScanSci Pi 学术搜索与 Deep Research

## 产品边界

学术搜索返回的是“发现线索”，不是可直接支撑科学结论的证据。只有合法获取并导入资料库的全文，经过句级检索、原文锚定和引用核验后，才能进入最终报告。

## 学术搜索

学术搜索是**只面向公开学术来源的联网发现流程**，不是知识库问答的另一个入口。它不读取、上传或写入用户的个人知识库；个人知识库只在用户显式选择“证据问答”或将全文导入后参与证据检索。

### 先确认、后联网

提交问题后，客户端先向本机请求一个不联网、不访问知识库的检索计划。计划由宿主程序做边界校验，并让用户在开始前确认或修改：

- 研究主题与 1–3 条检索式；
- 公开来源；
- 起始年份与候选数量；
- 本轮检索的公开范围说明。

确认后，才向已选择的公开来源发送这些简短检索式。这个交互采用成熟 Deep Research 产品中“先展示可编辑研究计划、再执行”的做法：把检索范围变成用户可审查的输入，而不是隐藏在模型或界面状态里。

宿主层会在任何网络调用前拒绝“忽略指令、读取本地资料、上传内容”式请求，限制主题和单条检索式长度为 180 个字符，过滤非白名单来源，并把用户改写的检索式限制为最多 3 条。相同校验也在任务创建 API 执行；不能只依赖前端界面。

默认按领域选择 OpenAlex、Semantic Scholar、Crossref、PubMed、Europe PMC、arXiv、OpenReview 与 DBLP 的适当子集。单个来源超时、限流或失败不会中断整个搜索。

结果先按 DOI 去重；没有 DOI 时使用规范化标题与年份去重。排序结合：

- 各来源排名的倒数排名融合（RRF）；
- 查询词与题名、摘要、关键词的相关性；
- 引用量与多来源一致性；
- 本地 BGE 向量相似度；
- 本地 CrossEncoder 重排。

每条记录保留来源列表、原始来源记录、分项得分、开放获取链接和 `discovery_only` 标记。模型不可用时会显式记录回退原因。

结果页必须同时展示：计划中的来源数、实际成功来源数、各来源返回量，以及失败或限流原因。因此“仅找到 3 篇”始终能区分为“检索范围本来只有 3 篇”还是“部分来源没有返回结果”。

### 不重复造轮子的复用边界

ScanSci 不把大型代理框架、全局论文图或系统综述筛选器硬编码进桌面端；它复用稳定开放接口，并保留与成熟开源工具互操作的边界：

| 能力 | 采用方式 | 参考实现 / 接口 |
| --- | --- | --- |
| 多源元数据发现 | 直接调用来源的公开 API；本地统一去重、审计和质量门 | [OpenAlex Works API](https://developers.openalex.org/api-reference/works/list-works)、[Semantic Scholar API](https://api.semanticscholar.org/api-docs/)、[Europe PMC REST](https://europepmc.org/RestfulWebService) |
| 种子论文扩展 | 后续从用户确认的种子论文调用推荐接口，而不是预建昂贵的全局图 | [Semantic Scholar Recommendations](https://api.semanticscholar.org/api-docs/recommendations) |
| 系统综述筛选 | 对需要 PRISMA 级筛选的任务，导出候选集交给专用工具；不在桌面端重写主动学习筛选器 | [ASReview](https://github.com/asreview/asreview)（Apache-2.0）、[PRISMA 2020 Flow Diagram](https://www.prisma-statement.org/prisma-2020-flow-diagram) |
| 全文证据问答 | 只在用户合法获取并索引的全文上运行；保留原文片段锚点 | ScanSci 本地证据索引，不与公开检索混用 |

`PaperQA` 的多提供方元数据、全文证据和引用质量分层是有价值的设计参考，但其代理运行时不直接嵌入本桌面端：ScanSci 已有本地证据处理链，应保持可审计、可离线回退的边界。[PaperQA](https://github.com/Future-House/paper-qa) 使用 Apache-2.0 许可。

## Deep Research

正式流程是持久、可取消和可恢复的研究运行：

1. 拆解研究问题、研究视角、检索式和纳入排除条件；
2. 将可编辑的公开来源检索计划呈现给用户确认；
3. 多源并行搜索，并根据视角覆盖度进行至多两轮补检；
4. 优先从开放获取链接、arXiv 或 DOI 合法获取全文，并导入当前资料库；
5. 只在已索引全文中检索句级证据；
6. 生成结构化综述、研究对比、争议、开放问题和局限；
7. 逐句检查引用是否存在、是否可回跳、是否真正支持相邻主张；
8. 保存报告、证据链接、检索轨迹、失败来源和未解决证据缺口。

如果全文不足，流程仍会保存检索候选和失败原因，但输出 `insufficient_evidence`，不生成科学结论，也不把“零条主张没有错误引用”显示成“报告已核验”。

## 入口

- 桌面端模式选择器：`学术搜索`、`深度研究`；
- 持久任务 API：`POST /api/runs`，使用 `academic_search` 或 `deep_research`；
- 学术搜索计划 API：`POST /api/academic-search/plan`；只生成经宿主校验的公开来源计划，不执行远程检索；
- Pi 工具循环：研究模式中的 `discover_papers` 使用同一套多源搜索和本地重排；
- 旧 Paper Atlas 入口继续保留，用于兼容已有任务和论文关系探索。

## 建议配置

- 一般检索：每源 10 条，最终保留 24 条；
- 深度研究：最多两轮，最终保留 36 条候选，优先获取 4 篇开放全文；
- 生物医学问题保留 PubMed 与 Europe PMC；计算机科学问题保留 arXiv 与 Semantic Scholar；Crossref 和 OpenAlex作为跨学科基础源。

API 限流属于预期外部状态。系统会对 `429`、`5xx` 做来源级节流和有界退避重试；仍失败时展示来源级错误并继续，而不是悄悄把缺失来源当成“没有相关研究”。
