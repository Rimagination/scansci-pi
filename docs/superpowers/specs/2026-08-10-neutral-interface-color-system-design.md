# ScanSci 中性色界面与主题色系治理设计

日期：2026-08-10
状态：设计已确认，等待实现计划

## 背景

ScanSci 已经具备浅色、深色和可选强调色，但现有实现仍混合使用语义变量、历史硬编码颜色和业务模块自定义色。结果是同一页面可能同时出现绿色选中态、蓝色按钮、青色图标和紫色插图。仅继续修补单个颜色不能阻止问题复发，因此需要把“强调色选择”升级为一套集中管理的产品色彩系统。

本设计采用用户确认的 B 方案：中性色界面。主题色用于表达交互和选择，不用于大面积装饰或为不同业务模块分配独立颜色。

## 目标

- 浅色和深色模式均使用一致的中性色阶管理背景、容器、文字和边框。
- 用户选择的主题色能够一致地影响主要交互，而不会造成整页染色。
- 消除设置、本地模型、模型服务、MCP、插件、知识库和对话页中的蓝绿紫混搭。
- 通过稳定的语义变量和自动检查，避免后续功能重新写入任意颜色。
- 保持错误、警告、成功、信息等状态色的含义稳定，并保留第三方品牌标识的原始颜色。

## 非目标

- 不重新设计页面信息架构、排版或组件尺寸。
- 不为不同业务模块分配不同品牌色。
- 不把所有状态色强制改为主题色。
- 不修改第三方 Logo、论文封面、用户图片和内容媒体本身的颜色。

## 核心原则

### 1. 中性色负责结构

应用背景、侧栏、页面容器、卡片、输入框、浮层、分隔线、正文和次要文字全部来自中性色阶。浅色与深色模式分别映射同一组语义角色，而不是由业务组件判断当前模式。

建议的语义角色包括：

- `--surface-app`：应用最外层背景；
- `--surface-sidebar`：导航和固定侧栏；
- `--surface-panel`：页面主面板；
- `--surface-card`：卡片和分组容器；
- `--surface-raised`：菜单、浮层和弹窗；
- `--surface-input`：输入框和可编辑区域；
- `--text-primary`、`--text-secondary`、`--text-muted`、`--text-disabled`；
- `--border-subtle`、`--border-default`、`--border-strong`；
- `--shadow-low`、`--shadow-medium`、`--shadow-high`。

业务组件只能选择角色，不能自行选择灰度值。

### 2. 主题色负责交互

每个可选主题色维护一套完整色阶，但界面只通过交互语义变量使用它。主题色用于：

- 主要按钮及其悬停、按下和禁用状态；
- 当前导航项、当前标签和当前筛选项；
- 焦点环和键盘操作反馈；
- 进度条、活动指示和少量交互图标；
- 插图中的小面积点缀。

对应语义角色包括：

- `--accent-solid`、`--accent-solid-hover`、`--accent-solid-pressed`；
- `--accent-on-solid`；
- `--accent-soft`、`--accent-soft-hover`；
- `--accent-border`、`--accent-focus-ring`；
- `--accent-text`、`--accent-icon`。

选中背景只使用低强度的 `--accent-soft`，不得把整张业务卡片染成高饱和主题色。

### 3. 状态色保持独立

成功、警告、错误和信息属于语义状态，不随用户主题色改变：

- 成功只表示操作完成或资源可用；
- 警告只表示需要注意但仍可继续；
- 错误只表示失败、阻塞或危险操作；
- 信息只表示中性提示，不承担业务模块装饰用途。

每种状态同样提供文字、柔和背景、边框和实色四类语义变量。普通按钮、MCP 卡片和本地运行组件不得借用信息蓝或成功绿作为装饰色。

### 4. 品牌色是受控例外

第三方服务商 Logo 和明确登记的品牌标识可以保留原始颜色。品牌色不得扩散到卡片背景、按钮、标题或边框。所有例外集中登记，避免业务 CSS 临时声明品牌色。

## 页面应用规则

### 设置与模型服务

- 页面、服务商列表和详情区域使用中性背景与中性边框。
- API 密钥、API 地址、模型名称等标签使用 `--text-primary` 或 `--text-secondary`，确保深色模式下达到可读对比度。
- 启用开关、保存按钮和当前服务商使用主题交互色。
- 服务商 Logo 保留品牌色，其余图标回归中性或主题交互色。

### 本地模型

- Agent 自动路由卡、应用运行组件和模型市场不再分别使用绿色、蓝色或青色容器。
- 卡片主体全部使用中性色；“添加本地能力”等主操作使用主题色。
- “可用”“需更新”“失败”等状态只使用对应状态色。
- `APP COMPONENTS` 等辅助标签使用中性次要文字；若可点击，才使用主题交互色。

### MCP 与插件市场

- 删除固定蓝紫色按钮、标签、轨道和插图主体。
- 卡片、筛选器和搜索框使用中性色；创建、加入、安装等主操作使用主题色。
- MCP 头图和轨道插图使用中性色主体加小面积主题色点缀。
- 来源网站或服务 Logo 可以保留品牌色。

### 知识库与对话

- 内容区、文件列表、右侧详情和对话气泡使用统一中性色阶。
- 当前知识库、当前历史对话和模型选择使用低强度主题选中态。
- AI 回复正文始终使用主要文字色，不因模块或模型来源改变颜色。

## 技术结构

### 单一令牌入口

颜色定义集中在主题层，组件层只引用语义变量。允许出现原始颜色值的位置限定为：

1. 中性色、主题色和状态色的中央令牌定义；
2. 受控品牌色登记表；
3. 图片、SVG 内容素材和渐变遮罩等无法由语义变量表达的媒体资源。

其余 CSS 和 JavaScript 模板不得新增十六进制、RGB、HSL 或固定颜色名称。

### 主题切换

明暗模式负责切换中性色和状态色的对比度映射；用户主题选择负责切换主题色阶映射。两个维度彼此独立：

- 明暗变化不改变主题色的身份；
- 主题色变化不改变页面结构层级；
- 组件不直接读取 `jade`、`ocean`、`plum`、`amber` 等主题名称。

### 兼容迁移

现有变量先映射到新语义角色，避免一次性破坏全部组件。随后按页面移除旧变量和硬编码颜色。迁移顺序为：

1. 设置与模型服务；
2. 本地模型；
3. MCP 与插件市场；
4. 知识库；
5. 对话、历史列表及其浮层；
6. 其余低频页面。

## 自动约束

- 增加颜色令牌契约测试，验证浅色、深色和所有主题均定义完整角色。
- 增加硬编码颜色扫描，允许列表仅包含中央令牌、状态色、品牌登记和已审核媒体资源。
- 对核心页面运行浅色/深色与四种主题组合的渲染检查。
- 对主要文字、次要文字、按钮、输入框和焦点环执行对比度检查。
- 在 `AGENTS.md` 中记录本设计的长期约束，要求新页面优先复用语义令牌。

## 验收标准

- 深色本地模型页不再同时出现绿色能力区和蓝色运行组件区。
- MCP 页面不再使用固定蓝紫色作为业务装饰色；切换主题后主要交互同步变化。
- 深色模型服务页的字段标签、模型名称和次要说明清晰可读。
- 切换四种主题色时，页面结构背景保持中性，主要交互和选中态正确变化。
- 错误、警告、成功和信息状态在所有主题下保持稳定含义。
- 新增未经登记的硬编码颜色会被自动测试阻止。

## 风险与回退

主要风险是旧页面依赖高特异性选择器，导致新令牌被历史颜色覆盖。实现时应先建立令牌，再逐页删除覆盖规则，并通过页面级检查确认。若某页面迁移出现回归，可暂时保留旧变量到新语义变量的兼容映射，但不能重新加入固定业务色。
